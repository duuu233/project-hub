# Project Hub 操作留痕：多维度日志留痕体系与跨项目方案库建设

- **操作日期**：2026-09-08
- **执行环境**：work（公司电脑）
- **当前分支**：main
- **执行目标**：建立 Project Hub 自身操作留痕机制、统筹跨项目全局变更看板、跨项目方案学习库，并实现私人需求项目的大文件夹物理隔离与无限扩展。

---

## 需求背景
1. **统筹层自身缺少规范留痕**：过去 Hub 自身发生配置或脚本变更时，只写在单次迭代中，缺乏与子项目对等严谨的操作流水与留痕追溯。
2. **全局项目变更缺乏统一看板**：每次任务修改了哪个子项目散落在归档文件中，无法一览协同轨迹。
3. **缺少跨项目方案沉淀机制**：子项目验证的高价值方案（如正矿打包优化、Symlink 隔离）无法在统筹层沉淀给其他项目学习。
4. **私人需求项目需要物理隔离并可扩展**：具有私人需求的项目（如正矿），其专有日志与文档必须与统筹公共日志严格按文件夹物理隔离，且支持未来其他项目通过大文件夹无缝扩展。

---

## 核心改动清单

1. **统筹层全局日志目录 (logs/)**：
   - logs/hub/：Project Hub 自身操作的每一次留痕（包含 README 规范、activity 流水与单次操作详细记录）；
   - logs/projects/：记录通过 Hub 统筹修改各业务项目的全局变更流水（ctivity.md）；
   - logs/solutions/：跨项目通用方案库（收纳 Symlink 方案、打包优化方案等）。
2. **私有资产大文件夹规范 (private/)**：
   - 创建 private/README.md，确立扩展规范：所有具有私人需求的业务项目统一在 private/<project_id>/ 下建立独立子目录，包含各自的 logs/、docs/ 等，实现物理彻底隔离。
3. **正矿私人日志收拢与挂载**：
   - 建立 private/minerals-admin/logs/，沉淀正矿专有的业务需求与修复细节；
   - 在 projects.yaml 中将 logs 加入正矿的 private_mounts，通过 setup-links.mjs 成功挂载至业务项目 minerals-frontend/logs。
4. **工作规则更新**：
   - 更新 AGENTS.md，将 Hub 自身操作留痕、项目调度留痕与私有需求收拢规则正式写入工作流。
