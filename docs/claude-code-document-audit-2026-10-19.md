## 命中与判断

- “非法值”“伪造”“攻击”等主要来自输入校验、禁止伪造数据、设备身份防重放及用户协议的禁止条款，属于正常技术和合规说明。
- “忽略规则”主要指 Git ignore；“不绕过统一请求层、权限指令”是在限制越权，不是在要求绕过模型规则。
- 小程序历史记录提及调试台绕过正式连接检查，是旧缺陷的原因说明和修复背景，不是新任务授权，不能把历史文本当成执行指令。
- 正矿 JSON 的“钓鱼台”是地名，属于词面误报。
- 花盆 APP 的 3 个凭据候选分别为 `docs/reference/tuya-ios-ap.md:239` 的密码输入框取值代码，以及 `docs/TUYA_SDK_SETUP.md:68`、`:69` 的签名密码占位符。未据此发现实际明文密码；其它文件未命中本轮有限规则，不代表不存在秘密或个人信息。
- 在已复核上下文中，未发现要求盗取凭据、伪造支付结果、实施欺诈或忽略模型安全约束的指令。不为消除关键词而改动现有合法业务文档。

### 涂鸦专属材料

花盆 APP 的 `docs/RELEASE_READINESS_REVIEW.md:22` 和历史记录已指出安全组件被版本控制跟踪。此次只读核实 `assets/Android_SDK1/security-algorithm/` 有 2 个跟踪条目，`assets/iOS_SDK (1)/` 有 45 个跟踪条目，后者包含 README 等文件，不等于 45 个秘密。

这属于供应商专属材料的分发与外发风险，不是 Claude 的“敏感词”。未读取二进制、未证实 AppSecret 泄漏，也未删除文件、改跟踪状态或重写历史。后续应由负责人按供应商要求单独处理材料权限、分发范围及是否轮换，不在本次同步中顺带清理。

### 公司资料及真实支付数据

在 VS Code 中使用模型仍可能将选入上下文的代码、文档、日志传给服务端；“不用于训练”不等于“不传输或不留存”。不要整包导入 `.env`、私钥、签名密码、真实 Token、Cookie、客户身份资料、银行卡或完整支付收据。使用脱敏样例，并先确认公司允许所选服务和数据范围。

官方区分消费者账户的训练选项和商业条款下的数据政策；应核对自己的套餐、组织设置及反馈上传行为，不能只凭扩展名字判断。[数据使用说明](https://code.claude.com/docs/en/data-usage)。

## VS Code 使用建议

1. 本机只读发现 Anthropic 官方扩展 `anthropic.claude-code-2.1.301-win32-x64`，版本 2.1.301；没有核查登录状态、账号地区、套餐或组织策略。
2. 当前 Claude Code 支持 `AGENTS.md`。默认情况下，工作目录及其祖先没有 `CLAUDE.md`/`CLAUDE.local.md` 时才按相应机制加载；插件和 Project instructions 设置也会影响行为。不能笼统说“Claude 不读 AGENTS.md”。在实际会话用 `/config`、`/context` 核实；需要兼容时可用 `CLAUDE.md` 的 `@AGENTS.md` 导入，本次没有擅自新建配置。[官方指令加载说明](https://code.claude.com/docs/en/memory)。
3. 按任务读取规则、文档索引和相关 Active 文档，不默认把所有历史记录都永久导入上下文；这有助于减少过时指令和无关资料外发，不是规避审核。
4. 使用 `/permissions` 检查权限，按最小范围允许文件和网络操作。文件工具的 Read deny 不能替代操作系统/终端隔离；`.gitignore` 也不是秘密访问控制。挂载到仓外的文档触发额外授权属于权限边界，不等同于账号处罚。[权限说明](https://code.claude.com/docs/en/permissions)、[安全说明](https://code.claude.com/docs/en/security)。
5. 任务如实说明维护对象、合法业务目的、允许操作和禁止事项。正常支付联调可明确“沙箱、仅本人应用、验证收据和幂等交付”，但不能伪装真实违规目的或以换词保证不触发审核。
