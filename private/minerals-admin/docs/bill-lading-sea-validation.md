# 提单海运日期与尾程校验口径

核对日期：2026-10-09；工作分支 `feature-v1.8.5`。

新增、编辑、详情使用共享海运组件 `src/views/bill-lading/bill-lading-list/components/SeaInfo.vue`。按用户确认，新增/编辑的预计到港日期和到港日期是否必填交由后端决定，前端允许两项同时为空，包括散货无尾程时的头程日期以及尾程日期。字段仍回显、编辑及按原模型提交。

删除尾程仍经过原来的删除确认，确认后允许删除最后一条，列表可以为空；移除“至少保留一条尾程信息”的拦截。首次初始化默认尾程与添加尾程时的集装箱分配检查沿用原实现。本次没有扩大到其他字段校验或状态切换逻辑。

父级提单表单会依次调用各模块的 `validate()`，所以海运组件保留该接口并返回 `true`。原接口只针对到港日期对执行 `validateField`，取消后不改成全表单校验，以免引入额外提交限制。日期规则、触发器、辅助校验函数均删除，防止清空日期时重复报错。

## 验证方法与结果

- 隔离示例运行真实 `SeaInfo` 组件，分别传 `pageType=1/2` 与集装箱/散货运输类型。
- 集装箱新增、编辑：尾程两个日期为空时 `validate()` 返回 true；确认删除仅剩的一条尾程，结果 `tailCount=0`、`valid=true`，提交模型仍保留头程。
- 散货新增、编辑：无尾程，头程两项日期均空，`validate()` 返回 true，页面不展示日期必填标记。
- 没有向真实后端新增、修改或删除业务数据；后端校验本轮没有联调。
- 最终 `npm run build:fast` 成功（30.6s）；类型检查仍失败，错误从基线 28 项变为 26 项。差异为移除的日期辅助校验消除了两项历史类型错误；没有新增错误。海运组件原有两项循环索引的 `string | number` 加法错误仍在，不扩大范围修复。
