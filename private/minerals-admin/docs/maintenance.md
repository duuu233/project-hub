# 长期维护与排障手册

> 最后核对：2026-08-17。

## 1. 一次维护任务的完整闭环

### 进入任务

```text
确认工作树
  -> 阅读 AI_CONTEXT 和主题文档
  -> CodeGraph 查询目标与 blast radius
  -> 确认配置/接口/运行时前提
  -> 实施最小改动
  -> 类型检查/构建/人工场景
  -> 检查 diff
  -> 更新本地知识
```

不要从页面文件直接开始修改。此项目的后端菜单、Store、TagsView、全局组件和 API 响应约定会造成跨目录耦合。

### 推荐的 CodeGraph 查询写法

定位：

```text
<组件/函数/文件名> 的职责、调用方、依赖方和 blast radius
```

流程：

```text
从 <入口符号> 到 <结果符号> 的完整调用链，包括动态 dispatch
```

修改前：

```text
修改 <符号> 的所有直接和间接影响，需回归哪些页面
```

一次查询尽量包含流程两端，不要用多次文本搜索手工拼调用链。

## 2. 高风险变更清单

### 登录和 Token

涉及：

- `views/login.vue`
- `store/modules/user.ts`
- `api/login.ts`
- `utils/auth.ts`
- `utils/request.ts`
- `permission.ts`

回归：

- 正常登录。
- 登录失败。
- 已登录访问登录页。
- 浏览器刷新后恢复用户。
- Token 过期 401。
- 退出登录。
- 带 redirect 登录返回。
- 统一 Token Cookie 兼容。

### 动态路由和菜单

涉及：

- `router/index.ts`
- `permission.ts`
- `store/modules/permission.ts`
- `api/menu.ts`
- Sidebar/TopNav/Breadcrumb/TagsView

回归：

- 首次登录生成菜单。
- 刷新动态路由深链接。
- 根路径跳首个有权限页面。
- 无任何菜单权限进入 no-access 404。
- 未知地址进入普通 404。
- 多级菜单与 ParentView。
- `userType === '00'` 时用户组管理菜单及深链接正常；非超级管理员时 `menuId=2000` 不进入侧栏、顶部菜单、搜索索引或动态路由。
- 用户信息缓存缺失或无效时按非超级管理员处理；确认 `userStore.getInfo()` 在 `generateRoutes()` 前已刷新 `Minerals-User-Info`。
- 外链/iframe。
- 侧栏高亮和面包屑。
- TagsView 缓存、刷新、关闭。

### 身份上下文切换

涉及：

- `layout/components/AuthContextSwitcher.vue`
- `utils/system-context.ts`
- `api/login.ts`
- Token、用户、路由、TagsView

回归：

- 企业/用户组/系统联动。
- 需要部门角色和不需要部门角色的系统。
- 换取新 Token。
- 刷新后用户信息和菜单属于新上下文。
- 原 TagsView 不残留。
- 切换账号后旧 localStorage 上下文不复用。
- 接口失败时保留当前有效身份。

### 统一请求层

涉及 `utils/request.ts` 时，必须抽样覆盖公开接口、鉴权接口、GET、POST、重复提交、401、业务错误、网络错误、上传、下载。

不要轻易改变“返回 `res.data`”这一行为。它会影响几乎全部 API 调用方。

### 公共表单和详情组件

涉及：

- `components/Details/`
- `common/post-loan/`
- 各业务 `template/handleDetail.vue`
- 全局上传、字典、分页组件

回归时按使用方而不是按组件自身选择页面。CodeGraph 没有自动化测试覆盖提示时，至少挑选不同业务域调用方。

### 代理订单与进口采购的定价条款

代理订单和进口采购单的新增、编辑、保存请求在顶层提交 `moreOrLessSign`、`moreOrLess`、`pricingBasisList`。定价依据项固定包含 `ingredients`、`value`、`isPriced`、`price`；`isPriced=0` 表示计价，`isPriced=1` 表示不计价。

维护约束：

- 成分名称必须由所选站点商品的成分字典带出，不允许手工修改；商品或站点变化时要重建定价依据并清除不属于新商品的旧成分。
- 进口采购新增或编辑时，选择代理订单后必须使用代理订单列表当前选中项的 `pricingBasis`、`moreOrLessSign` 和 `moreOrLess` 回填定价条款；定价依据为空时按所选订单商品成分生成空白定价行，不得沿用上一代理订单的数值；已选择代理订单时，成分要求、溢短装符号和溢短装数值只读，是否计价仍可编辑。
- 代理订单和进口采购单的溢短装由符号和值组成，两者均必填；数值 `0` 为有效输入。
- 详情优先读取 `pricingBasisList`；代理订单兼容 `orderInfo.pricingBasis` JSON 字符串，采购单兼容同名 `pricingBasis` 字符串。
- “AI助手·小乾”识别代理单合同或采购合同后，需要同时回填溢短装和定价依据；进口采购已选择代理订单时，以代理订单选中项为准，不使用识别值覆盖这些锁定字段；编辑页的差异确认也必须比较这些字段，避免只存在新字段差异时误判为一致。
- 回归至少覆盖：手工选商品自动带出成分、必填吨度校验、是否计价默认“是”、新增/编辑请求体、详情只读回显、AI 新增回填、AI 编辑差异覆盖，以及切换站点/商品后无旧定价行残留。

## 3. 常见故障定位

### 登录后进入 404

依次确认：

1. `/system-service/user/getInfo` 是否成功并返回用户/权限。
2. `/system-service/menu/getRouters` 是否返回菜单数组。
3. `permissionStore.routeLoadCompleted`、`hasAccessibleRoute` 是否符合预期。
4. 后端菜单 `component` 是否存在于 `src/views`。
5. 路由 name 是否重复。
6. 404 通配路由是否在动态路由之后注册。
7. 当前地址是否是旧系统上下文下的无效路径。

### 菜单显示但页面空白

确认：

- 组件路径大小写和层级。
- `.vue` 文件默认导出/SFC 是否可编译。
- 浏览器控制台是否有动态 import 错误。
- 页面依赖的全局组件、自动导入和类型声明是否仍存在。
- AppMain/KeepAlive 是否因 name 不一致缓存了错误实例。

### 刷新后页面丢失或回首页

区分：

- 前端动态路由尚未初始化。
- 服务端没有 HTML5 history fallback。
- 当前用户已无路由权限。
- 首个可访问路由计算变化。
- 身份上下文切换后旧 URL 无效。

先看网络请求和路由守卫，不要直接添加静态路由掩盖问题。

### 接口请求成功但页面读取不到数据

统一请求层已经解包 AxiosResponse。检查调用方是否错误读取了：

```ts
res.data.rows
```

常见正确形式可能是：

```ts
res.rows
res.total
```

但某些后端接口本身又把业务数据放在 `data` 字段中，因此必须看该接口真实契约，不能全局机械替换。

### POST 被提示重复提交

检查：

- 是否在 1 秒内提交相同 URL 和 data。
- 按钮是否同时绑定 click 与 form submit。
- watcher 或生命周期是否重复调用。
- 确实需要重复时，才设置 `headers.repeatSubmit = false`。

### 中文在终端显示乱码

先检查：

- PowerShell/终端 code page。
- 文件真实编码。
- 编辑器和浏览器显示。
- Git diff 是否出现整文件重写。

如果浏览器和编辑器正常，只是命令行显示异常，不要转码源码。转码前必须备份并确认差异范围。

### 构建内存或速度问题

- 标准构建已配置 `NODE_OPTIONS=--max-old-space-size=4096`。
- 快速检查可使用 `npm run build:fast`。
- 大依赖已手工拆包；修改 `manualChunks` 后检查循环 chunk 和首屏加载。
- gzip 只压缩大于 10 KB 的文件，fast 模式明确关闭压缩。

## 4. 当前技术债与风险

### 缺少自动化测试

当前未发现测试框架和测试文件。影响：

- CodeGraph 通常会提示关键符号无测试覆盖。
- 公共组件和跨模块修改主要依赖类型检查、构建和人工回归。
- 修复高价值缺陷时应优先留下可重复验证方案，即使暂时只是最小脚本或明确的人工步骤。

### 类型严格度较低

`strict: false` 和大量 `AnyObject` 会隐藏字段拼写、null、响应层级问题。新代码逐步收紧边界类型，但避免一次任务内全仓严格化。

### 大型单文件组件

多个 `handleDetail.vue` 超大且职责混合。重构顺序建议：

1. 先用 CodeGraph 定位稳定边界。
2. 提取纯数据转换和校验函数。
3. 提取无跨页状态的 composable。
4. 最后拆视觉子组件。
5. 每一步保持 API 和 pageType 行为不变。

不要一次性重写整个业务表单。

### 重复业务组件

应收、应付、仓储、采购选择等目录存在相似组件。抽象前先比较真实字段和流程差异，避免为了减少文件数量制造充满条件分支的“大一统组件”。

### 环境命名不一致

test mode 与 `.env.staging` 不对应。调整需要同时考虑 npm scripts、Vite mode、代理目标、BASE_API 和部署流水线。

### 本地文档不可跨机同步

这是当前明确配置，而不是文档系统缺陷。跨机器时 Git 只同步代码；本地知识必须重新核对。若未来需要团队共享，应由维护者明确决定哪些文档改为受 Git 跟踪，并调整 `.gitignore`。

## 5. 文档更新触发器

| 事件 | 操作 |
| --- | --- |
| 依赖升级 | 更新版本、兼容风险、验证命令 |
| 新增微服务前缀 | 更新代理/环境说明和 API 域 |
| 登录或 Token 变化 | 更新架构和登录回归清单 |
| 菜单结构或路由生成变化 | 更新动态路由流程与排障 |
| 身份字段变化 | 更新上下文数据模型与切换回归 |
| 新增一级业务目录 | 更新业务域地图 |
| 新增 AI 文件类型 | 更新 AI 架构、目标页面和回填规则 |
| 引入测试框架 | 删除“无自动化测试”旧说明，补测试命令和目录 |
| 构建/部署变化 | 更新环境表、构建与部署前提 |

## 6. 变更记录模板

对于影响长期维护认知的变更，可在对应文档末尾添加简短记录：

```markdown
## 变更记录

- YYYY-MM-DD：变更事实；涉及入口；验证方式；仍待确认事项。
```

只记录结构性变化，不记录每次页面文案或样式微调。

## 7. 交付信息模板

每次完成代码任务，向维护者说明：

- 结果和行为变化。
- 修改的关键文件。
- CodeGraph 发现的主要影响范围。
- 实际执行的验证命令及结果。
- 未验证的人工场景或剩余风险。
- 是否更新了本地维护文档。

不要声称没有执行过的验证已经通过。
