### 组件与数据规则

- `WarehouseUi/detail-cards.ts` 是无副作用的响应映射；页面用同一个 `detailCards` 派生顶部、时间节点、关联信息，避免分别取不同来源。原 `DetailHeaderCard` 和 `WarehouseDetailLayout` 继续承担视觉展示，不重画已有图标。
- 单位优先来自当前响应及现有字典；协议已声明的1千克/2吨作为单位字典尚未返回时的兜底。重量四位小数，0正常展示；缺明细重量不假定为0，不把不同单位的明细直接相加；缺值显示 `--`。仓库名称优先用当前详情值，缺少时才按当前仓库ID查已加载列表。
- 入库计划明细沿用 `planWeight` 等既有字段；入库单沿用 `stockPlanWeight / planWeight` 及 `stockWeight`。出库单“计划重量”以关联计划 `totalWeight` 优先，实际重量按本单出库明细，不能把当前单重量冒充整个计划。
- 日期缺失或非法不使用今天兜底。出库单顶部、时间轴和关联卡优先用本单 `stockOut.stockOutPlanDate`，再回退关联计划；实际日期统一用本单。日期选择器格式统一后，接口日期也能正常回显。
- `useWarehouseDetailRequest.ts` 保留一份原始详情快照，给原表单的值先深拷贝，避免表单日期、货物、附件归一化污染卡片。仅最新请求可更新；刷新期间卡片占位、按钮禁用；失败清空卡片并提示重试，成功重试恢复；退出后不接受迟到结果。不改页面原有新增/编辑提交函数、选择监听或关闭计划逻辑。
- 出库计划的 `stockDeliveryDetailVO.fileList` 对应提货单附件，响应 `fileList` 对应出库计划附件，分开只读展示；已出库行没有 `stockOutId` 时禁用查看按钮，原带ID跳转保留。有实际 `stockOutNo` 时优先显示，不拿无意义样例补数据。
- 原稿出库单关联卡中误写的“入库重量/日期”按接口及出库业务改为“出库”。库存查询、日志、存放预警沿用此前确认的三个列表，不新增无设计依据的详情或编辑页。

- `src/components/WarehouseUi/` 提供统计卡、详情侧栏、附件布局、表格空态和只读输入式单元格，沿用现有组件和视觉令牌。

- 新增/编辑沿用原有选择弹框、字典、校验、附件上传、权限和提交逻辑。新增展示字段不向后台添加未知的保存参数。出库计划提货单附件和计划附件已分别读取详情中的两个文件列表；已出库货物展示取可用响应字段，否则为空。
