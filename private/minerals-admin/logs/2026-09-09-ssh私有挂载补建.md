# 正矿 ssh 环境私有挂载补建（docs / logs / AGENTS / AI_CONTEXT / .codegraph）

- **执行日期**：2026-09-09
- **执行环境**：ssh（SSH 开发机，`/pgdata/pg/dh/minerals-frontend`）
- **项目**：minerals-admin（正矿）
- **仓库分支**：`feature-v1.8.3`（本次不产生团队仓库提交，仅本机链接与忽略配置）

---

## 背景

私有挂载方案 2026-09-08 在 work 电脑落地，`projects.yaml` 的 `private_mounts` 是三端共用的同一份定义；但每台机器仍要各自执行一次 `setup-links` 把链接建出来。ssh 开发机一直没建：仓库里既没有 `AGENTS.md`、`AI_CONTEXT.md`、`logs/`、`.codegraph/`，`docs/` 还是一个本机遗留的实体目录，`.git/info/exclude` 也没有对应忽略行。此前在这台机器上的几轮正矿任务都是直接读写 Hub 的 `private/minerals-admin/` 原文件完成的。

## 冲突与处理

首次 `--dry-run` 直接报错：

```
Real source exists: /pgdata/pg/dh/minerals-frontend/docs.
Use --migrate only when the private target is absent; never overwrite either copy.
```

即业务仓库里有实体 `docs/`、Hub 私有目标 `private/minerals-admin/docs/` 也存在，脚本两边都不覆盖，`--migrate` 也不适用（它只针对私有目标尚不存在的首次迁移）。

本机 `docs/` 里只有 `build-opt/`，是 2026-08-25 打包优化留下的原始产物（baseline / stage2 / stage3 / stage3b / stage4 的 build 日志、dist 清单、metrics、peak-rss，加 `apply-stage*.py`、`measure-build.sh`、`report-dist.sh` 等脚本，24 个文件 / 601894 字节），Hub 私有 docs 里只有该次优化的成文记录（`build-optimization.md`、`build-optimization-record-2026-08-25.md`），没有这批原始数据。

处理：`cp -a` 复制到 `private/minerals-admin/docs/build-opt/`，`diff -r` 校验两边完全一致（24 个文件、字节数相同）后删除仓库内原目录与空的 `docs/`，再重新执行脚本。挂载后这批文件在仓库里仍是原来的 `docs/build-opt/` 路径。

## 执行结果

```
node scripts/setup-links.mjs --env ssh --project minerals-admin
mount: .codegraph    -> private/minerals-admin/.codegraph
mount: docs          -> private/minerals-admin/docs
mount: AGENTS.md     -> private/minerals-admin/instructions/AGENTS.md
mount: AI_CONTEXT.md -> private/minerals-admin/instructions/AI_CONTEXT.md
mount: logs          -> private/minerals-admin/logs
```

校验：

- 5 个挂载点 `readlink -f` 均指向 `/pgdata/pg/dh/project-hub/private/minerals-admin/` 下的真实文件，通过链接可正常读到 `docs/README.md`、`AI_CONTEXT.md`、`logs/activity.md`、`docs/build-opt/`。
- `git check-ignore -v`：`docs`、`logs`、`.codegraph` 命中脚本写入的 `.git/info/exclude`；`AGENTS.md`、`AI_CONTEXT.md` 本来就被团队 `.gitignore` 第 29 / 30 行忽略。
- 团队仓库 `git status --short --branch` 只剩 `## feature-v1.8.3`，工作区干净，链接不会污染团队 Git。

## 遗留

- **本机没有安装 `codegraph` CLI**（`command -v codegraph` 为空），所以 `.codegraph/` 只是把 Hub 里的索引库链过来，内容仍是 work 机器上次 sync 的快照，本机无法执行 `codegraph sync`；ssh 环境下定位代码继续用源码检索。
- home 电脑没有正矿仓库，`environments/home/projects.local.yaml` 里也没有 minerals-admin 映射；日后在那台机器 clone 后需先补映射，再执行 `node scripts/setup-links.mjs --env home --project minerals-admin`。
