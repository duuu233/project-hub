## 实施范围

`apps/qianrong` 提供 `npm run demo:modules` 与 `/modules-demo.html` 独立开发入口。13 个侧栏模块复用现有业务列表，7 个模块接入原新增/编辑/查看表单，字典数据、分配用户和分配角色路由也可预览。页面来源与详细操作见应用公开 `MODULES_DEMO.md`。

已有用户组/角色关联系统草稿、左右菜单权限树和个人中心交互保留。右上角管理员/只读视角使用原权限指令重新挂载组件，仅验证按钮展示；不能替代真实路由守卫、后端授权或数据权限验收。

S12 新增无 API 的接口日志组件：关键词、方向、结果、日期筛选，客户端分页、时间/耗时排序，列显隐、全屏，请求/响应详情与本地 CSV。数据由 `records` 传入；示例仅在独立入口注入，没有新增正式菜单或伪造后端查询/详情/导出端点。递归屏蔽敏感键、手机号及 Bearer 文本，导出不含请求/响应正文并处理 CSV 转义。真实日志仍须服务端脱敏。

S13 静态登录页参照原通用登录字段，支持手机号、企业类型、租户所属企业和密码必填检查，完成后进入静态列表；不建立会话，不改现有登录、SSO、Token、守卫和缓存键。S14 使用原个人中心，资料在本次预览内存中保存，取消恢复当前资料，刷新恢复示例；密码/头像不模拟成功。

续接前一天已证实的修正：开发代理切到 `https://dev-qianrong.ftechain.com/api-qianrong`；`systemList` 使用 GET + params；6 个导出、导入模板和用户导入共 8 处直接地址补全 `/api-qianrong`，两种日志使用 `/monitor` 域。新版 JSON 的路径/方法重新核对通过。

用户组/企业旧导出共用角色地址、18 个 Swagger 未列出的旧辅助包装、角色 `roleSystems` DTO 兼容继续待确认。菜单权限从用户组迁移到系统管理仍按已确认安排等待后端。未把这些疑点映射到名称相近接口，未宣布真实保存或权限刷新已兼容。

## 静态与生产边界

独立配置替换 request、认证工具、用户 Store、路由辅助和同步字典读取；示例不读写正式 Cookie/Token/用户缓存，不启动业务代理。资料 PUT 只修改示例内存；其他写入适配器提示未接入并拒绝，不返回业务保存成功。HTTP 业务路径与非 GET/HEAD 由本地预览服务返回 403。

正式 `npm run build` 继续使用原入口，不包含 `modules-demo.html` 和示例路由；独立入口的配置标记也阻止通过普通开发命令误启动。接口日志组件可供后续正式接入，但当前无后端连接。没有真实业务调用、登录、写入、导入导出、部署或 PR。

验证和最终提交见 [本轮历史](history/2026-10-14-qianrong-static-modules.md)。
