# 三模块菜单权限统一目录树

当前口径：2026-10-22 work。用户要求系统管理、用户组管理、角色管理的菜单权限样式与交互统一为正矿式 tree，不能继续保留角色横向“菜单/操作权限表”。此前系统→用户组→角色授权边界继续适用，不是重新搬迁权限归属。

## 参考与实现边界

- 正矿本轮同步 feature-v1.8.5 至2c6055f8，仅作只读参考。其 `src/views/system/role/index.vue` 旧菜单授权弹窗有真实 `el-tree`，含复选框、展开/折叠、全选/全不选，`.tree-border` 为白底浅色边框4px圆角。
- 正矿当前独立角色/用户组页面也存在横向PermissionTable；本轮依用户明确的“tree结构”选取前述目录树交互，不继续复制横向表，不将正矿其它业务逻辑移植到qianrong。
- 只改qianrong，不修改正矿、qianlian、packages、接口包装、权限来源及保存DTO。

## 统一交互

- 目录→页面→按钮纵向缩进，默认展开；通过“展开/折叠”切换，也可按节点箭头/标签展开。半选显示父级分支的部分权限，不把半选误当全部子权限已授予。
- 勾选父级会选择其可操作子级，单选子级补齐树内祖先；取消分支清理可操作后代，保留其它分支及所需祖先。全选/全不选作用于当前系统的可操作树，不跨系统、不补树外ID，锁定的原授权保留。
- 搜索和仅看已选仅改变展示，不改变勾选或提交数组。折叠、展开、初始化、详情回显均不得隐式授权；尤其旧数据只有目录/页面ID时不能因为渲染自动勾选所有后代。
- 受控数组保持API编号类型，保留int64字符串与0；重复/缺失节点拒绝。系统和用户组停用规则沿用原始授权可操作性；角色继续使用原disabled规则。
- 详情/在途状态禁止勾选与全选，展开、搜索仍可用；每系统菜单草稿及原角色草稿/撤权确认不变。用户组原额外“全选可用菜单/清空”按钮合并至统一工具栏，避免三处交互不一致。
- 使用check-strictly防止组件初始化时把父ID隐式扩成子授权，手动受控联动与半选，提交仍走原业务层。角色适配只回传叶子的新增/删除差异，不替换原权限边界及组授权上限。
