## 1. 一页结论

> **行级用“身份 × 人员”两项选择代替表达式，列级用“菜单默认 + 角色差异”代替整份复制，复用全部收敛到已有的用户组上。**
> 开发侧每个列表只加一行后端注解；前端一个配置组件，在用户组与角色两处复用；运营侧新企业入驻零配置。

| 设计点 | v1.0 | v2.0 | 收益 |
| --- | --- | --- | --- |
| 企业隔离 | “本企业”是可选预设档 | 系统硬边界，不可配置 | 不会被误配掉 |
| 行级规则 | 字段 + 操作符 + 值，条件组 OR / 组内 AND | 参与身份（多选）× 人员范围（单选） | 免做表达式引擎；运营只需勾选 |
| 合作关系 | 维护企业关系网络，动态计算下游企业 | 直接取单据上的参与方字段 | 业务录单即生效 |
| 复用 | 策略包 + 企业 / 用户组 / 角色三层继承 | 用户组即策略包，角色只存例外 | 概念只剩两个 |
| 列级 | 逐角色整份配置（现状需“导入菜单列字段”） | 菜单默认 + 角色差异 | 新字段自动兜底 |
| 规则状态 | 四态状态机 + 字段漂移修复 | 只有派生的显示状态，不存库 | 无修复流程 |
| 多角色合并 | 行规则“取宽松” | 按角色整体 OR | 修正越权漏洞 |
| 列表与接口对应 | 前端维护 23 条对照 | 资源码 = 菜单权限标识前缀 | 列表 / 详情 / 导出共用 |

## 2. 背景与目标

### 2.1 现状

```mermaid
flowchart LR
    SYS["系统<br/>菜单授权上限"] --> UG["用户组<br/>在系统授权内勾选菜单"]
    UG --> ROLE["角色<br/>归属企业 + 用户组<br/>在用户组内选菜单"]
    ROLE --> USER["账户<br/>00/01 平台 · 02/03 企业<br/>多角色、可切换企业身份"]
    ORG["企业"] -.->|"绑定多个用户组"| UG
    ROLE -.->|"dataScope 全局单选"| DS["行级：全部 / 自定义部门 /<br/>本部门 / 本部门及以下 / 本人"]
    ROLE -.->|"导入后逐个修改"| RC["列级：角色列字段"]
    MC["菜单列字段<br/>默认策略 HIDDEN"] -.->|"整份复制"| RC
```

| 能力 | 已有 | 缺口 |
| --- | --- | --- |
| 功能权限 | 系统 → 用户组 → 角色逐层收窄，权限两列表格三处复用 | — |
| 行级 | 角色级 dataScope 五档（“本企业”已从选项中去掉） | 不能按列表区分；不能按参与身份切片 |
| 列级 | 菜单列字段 7 接口、角色列字段 6 接口，三态 + 两种脱敏 | 角色要整份导入；菜单新增字段不会同步给角色 |
| 预览 | 调列表接口并多传 `previewRoleId` | 列表与接口的对应关系写死在前端 |

### 2.2 业务主体

qianrong 的参与方是固定的几类：

```mermaid
flowchart LR
    P(("平台方")) --- CORE["核心企业"]
    CORE --- FIN["融资企业"]
    FIN --- BANK["资金方 / 银行"]
    FIN --- SUP["监管方"]
    SUP --- WH["监管仓库"]
    BANK --- CORE
```

业务单据（准入、授信、项目制方案、合同等）天然带有这些参与方字段。因此数据可见性归结为两个问题：

1. 当前企业**以什么身份**出现在这张单据上？——决定能不能看；
2. 企业内部**哪些人**能看？——决定部门 / 本人范围。

### 2.3 设计目标与非目标

| 目标 | 衡量方式 |
| --- | --- |
| 开发简单 | 接入一个列表 = 加一行注解，不写过滤 SQL |
| 自由度够用 | 覆盖“按列表区分”“按身份切片”“按人员收窄”“字段隐藏 / 脱敏” |
| 复用性强 | 一处默认，多处继承；改默认，未设例外的角色自动跟随 |
| 运营便利 | 新企业零配置；典型配置不超过两次选择 |

**非目标**：不做通用规则引擎和表达式编辑器；不建企业关系网络；不做字段级审批流。

### 3.1 谁配置什么

```mermaid
flowchart TB
    DEV["开发"] -->|"声明"| A1["列表资源码、参与身份字段、列字段"]
    PA["平台管理员<br/>账户类型 00"] -->|"配置"| A2["系统菜单、列字段默认策略、<br/>用户组的菜单 / 数据默认 / 列差异、<br/>企业绑定用户组"]
    EA["企业管理员<br/>账户类型 02"] -->|"配置"| A3["本企业角色：菜单裁剪、<br/>数据例外、列例外、分配账户"]
    BU["业务人员<br/>01 / 03"] -->|"使用"| A4["按生效权限查看列表、详情、导出"]
```

### 3.2 核心场景

| 编号 | 场景 | 期望体验 |
| --- | --- | --- |
| S1 | 新的融资企业入驻 | 绑定“融资企业组”后立即可用，不进权限模块 |
| S2 | 企业经办员只看自己经办的单据 | 角色上把人员范围改成“仅本人”，一次选择 |

| S4 | 资金方不能看到平台服务费 | 在资金方组的列策略里把该字段设为隐藏 |
| S5 | 业务新上线一个字段 | 自动隐藏，平台管理员在菜单列字段放开一次即可 |
| S6 | 想确认某角色到底能看到什么 | 在配置页一键预览真实样本 |

## 4. 概念模型

### 4.1 分层

```mermaid
flowchart TD
    subgraph 资源层
        SYS["系统<br/>菜单、按钮、列表资源、列字段定义"]
    end
    subgraph 边界层
        ENT["企业<br/>硬隔离边界，不可配置"]
    end
    subgraph 策略层
        UG["用户组<br/>菜单上限 + 默认行规则 + 列策略差异"]
    end
    subgraph 岗位层
        ROLE["角色<br/>菜单裁剪 + 行规则例外 + 列策略差异"]
    end
    subgraph 使用层
        USER["账户<br/>当前企业身份下的角色集"]
    end
    SYS -->|"划定上限"| UG
    ENT -.->|"绑定"| UG
    UG -->|"继承，只存例外"| ROLE
    ROLE -->|"1 : N"| USER
```

### 4.2 术语

| 术语 | 定义 |
| --- | --- |
| 列表资源 | 菜单中的 C 类“列表”页面；资源码取其权限标识前缀，如 `access:coreOrg:list` → `access:coreOrg`，同前缀的详情、导出共用 |
| 参与身份 | 本企业在单据中的身份，如核心企业、融资企业、资金方、监管方、监管仓库；由开发按单据字段声明 |
| 人员范围 | 全部 / 本部门 / 本部门及以下 / 指定部门 / 仅本人，即现有 dataScope |
| 行规则 | 参与身份 × 人员范围；有“默认规则”和“列表例外”两种 |
| 列策略 | 字段的 可见 / 脱敏 / 隐藏；默认值在菜单列字段上 |
| 例外 / 差异 | 角色或用户组上与上级不同的设置；没有差异即为继承 |
| 生效权限 | 当前企业身份下所有角色合并后的结果 |

### 4.3 数据模型

```mermaid
erDiagram
    SYS_ORG }o--o{ SYS_USER_GROUP : "企业绑定用户组"
    SYS_USER_GROUP ||--o{ SYS_ROLE : "角色归属"
    SYS_USER }o--o{ SYS_ROLE : "分配角色"
    SYS_MENU ||--o{ SYS_MENU_COLUMN : "列表字段定义"
    SYS_USER_GROUP ||--o{ SYS_DATA_RULE : "默认与例外行规则"
    SYS_ROLE ||--o{ SYS_DATA_RULE : "例外行规则"
    SYS_MENU ||--o{ SYS_DATA_RULE : "列表例外"
    SYS_ROLE ||--o{ SYS_ROLE_COLUMN : "列策略差异"
    SYS_MENU ||--o{ SYS_ROLE_COLUMN : "所属列表"

    SYS_MENU {
        bigint menu_id PK
        char menu_type "C 为页面"
        varchar perms "权限标识，前缀即资源码"
    }
    SYS_MENU_COLUMN {
        bigint id PK
        bigint menu_id FK
        varchar field_code
        varchar field_type "语义类型，决定默认脱敏方式"
        varchar policy "默认策略，新建为 HIDDEN"
        varchar mask_type
    }
    SYS_DATA_RULE {
        bigint id PK
        varchar owner_type "GROUP 或 ROLE"
        bigint owner_id
        bigint menu_id "为空表示默认规则"
        varchar parties "参与身份，多选"
        char person_scope "沿用 dataScope 取值"
        varchar dept_ids "指定部门时使用"
    }
    SYS_ROLE_COLUMN {
        bigint id PK
        bigint role_id FK
        bigint menu_id FK
        varchar field_code
        varchar policy "只存与默认不同的值"
        varchar mask_type
    }
```

> 新增的只有 `SYS_DATA_RULE` 一张表；菜单列字段、角色列字段沿用现有表，角色列字段改为“差异”语义。用户组列策略差异在第二阶段沿用同表加 `owner_type`。

## 5. 权限规则设计

### 5.1 功能权限

沿用现有“权限名称 / 操作权限”两列表格与系统 ∩ 用户组 ∩ 角色的收窄规则，本方案不改。

### 5.2 行级：身份 × 人员

```mermaid
flowchart LR
    subgraph RULE["一条行规则"]
        direction LR
        P["参与身份<br/>多选，之间为 OR<br/>☑ 作为核心企业<br/>☑ 作为融资企业<br/>☐ 作为资金方"]
        AND(("AND"))
        S["人员范围<br/>单选<br/>◉ 全部<br/>○ 本部门<br/>○ 仅本人"]
        P --- AND --- S
    end
```

- 只显示该列表**声明过**的参与身份。
- 平台账户的参与身份为“全平台”；第二阶段可收窄为“指定产品 / 资金方 / 监管方”（现有 dataScope DTO 中已有 `productIds / regulatoryIds / bankIds` 字段，可沿用这个方向）。
- 个别列表的特殊过滤（如“大额单据”）由开发在注解中定义为**具名选项**，运营仍然只是勾选。

**规则查找顺序**（每个角色独立查找，命中即止）：

```mermaid
flowchart LR
    R1["角色<br/>本列表例外"] -->|"未设置"| R2["角色<br/>默认规则"]
    R2 -->|"未设置"| G1["用户组<br/>本列表例外"]
    G1 -->|"未设置"| G2["用户组<br/>默认规则"]
    G2 -->|"未设置"| S0["系统兜底<br/>企业账户：本企业参与的全部 × 现有 dataScope<br/>平台账户：全平台 × 现有 dataScope"]
```

> 系统兜底等于今天的行为，所以第一阶段上线时，没配置的角色不受影响。

### 5.3 列级：菜单默认 + 差异

```mermaid
flowchart LR
    RC["角色差异"] -->|"无"| GC["用户组差异<br/>第二阶段"]
    GC -->|"无"| MC["菜单列字段默认"]
    MC -->|"新字段"| H["HIDDEN"]
```

| 策略 | 列表 | 详情 | 导出 |
| --- | --- | --- | --- |
| 可见 VISIBLE | 正常显示 | 正常显示 | 输出 |
| 脱敏 MASKED | 掩码显示 | 掩码显示 | 输出掩码 |
| 隐藏 HIDDEN | 整列不显示 | 该项不显示 | 不输出该列 |

- 脱敏方式 FULL（`***`）或 KEEP_FIRST_LAST（`1101**********1234`），默认值由字段语义类型决定（手机号、证件号、银行卡、金额），运营通常只需选三态。
- 处理统一在后端响应环节完成；前端隐藏只是展示配合，不承担安全职责。

### 5.4 多角色合并

```mermaid
flowchart TB
    subgraph 角色1
        A1["作为融资企业"] --- X1(("AND")) --- B1["仅本人"]
    end
    subgraph 角色2
        A2["作为资金方"] --- X2(("AND")) --- B2["全部"]
    end
    X1 --> OR(("OR"))
    X2 --> OR
    OR --> RES["生效：(融资企业 且 本人) 或 (资金方 且 全部)"]
```

| 维度 | 合并方式 |
| --- | --- |
| 功能 | 并集 |
| 行 | 按角色整体 OR。**不能**按维度分别并集——上例若拆开合并会变成“(融资企业 或 资金方) × 全部”，越权看到融资企业的全部单据 |
| 列 | 三态取最宽：VISIBLE > MASKED > HIDDEN；同为 MASKED 时取最严方式（FULL 优先） |
| 范围 | 只合并当前登录企业身份下的角色 |

## 6. 关键流程

### 6.1 查询时的权限计算（运行时）

```mermaid
sequenceDiagram
    autonumber
    actor U as 账户
    participant FE as 前端
    participant API as 列表 / 详情 / 导出接口
    participant IC as 数据权限拦截器
    participant C as 生效权限缓存
    participant DB as 数据库

    U->>FE: 打开列表
    FE->>API: 查询请求（携带当前企业身份 Token）
    API->>API: 校验按钮权限，如 access:coreOrg:list
    API->>IC: 进入注解声明的资源 access:coreOrg
    IC->>C: 取「账户 + 当前企业」的生效规则
    alt 缓存未命中
        C->>C: 按 5.2 / 5.3 查找并合并各角色规则
    end
    C-->>IC: 行规则 + 列策略
    IC->>IC: 企业账户先追加硬隔离条件
    IC->>DB: 追加行过滤后的 SQL
    DB-->>IC: 结果集
    IC->>IC: 按列策略隐藏 / 脱敏字段
    IC-->>FE: 处理后的数据
    FE-->>U: 渲染（隐藏列不出表头）
```


### 6.3 平台管理员修改用户组默认规则


### 6.4 企业管理员为角色设例外（场景 S2 / S3）

```mermaid
flowchart TD
```

## 7. 状态设计

> 规则本身不存状态字段，下面的状态都由现有数据实时推导出来，用于界面展示和运营理解。

### 7.1 角色在某个列表上的规则状态

```mermaid
stateDiagram-v2
    state "有查询权限" as Q {
        state "继承中" as INH
        state "已设例外" as EXC
        [*] --> INH
        INH --> EXC: 修改行规则或列策略
        EXC --> INH: 恢复继承
        EXC --> INH: 修改后与上级一致，差异自动清除
    }
    state "休眠" as SLEEP
    [*] --> Q: 角色获得该列表查询权限
    Q --> SLEEP: 取消查询权限
    SLEEP --> Q: 重新授予查询权限
    note right of SLEEP
        规则保留不删
        恢复后回到休眠前的状态
        例外不丢失
    end note
```

| 状态 | 界面表现 |
| --- | --- |
| 继承中 | 灰色标签“继承自用户组 XX”，选项显示上级的值 |
| 已设例外 | 蓝色标签“例外”，旁边有“恢复继承” |
| 休眠 | 该列表不出现在数据权限页签与预览中；重新勾选查询后恢复 |

## 10. 异常与安全

| 情况 | 处理 |
| --- | --- |
| 角色取消列表查询权限 | 规则进入休眠，不删除；没有查询权本就访问不到 |
| 用户组收窄参与身份 | 角色上超出的身份在生效时被截断，界面标红提示“超出用户组范围” |
| 列字段被删除 | 角色差异行忽略；保存时顺带清理 |
| 新增列字段 | 默认 HIDDEN，所有角色不可见 |
| 列表未声明参与身份 | 兼容期：保持旧逻辑并告警；强制期：企业账户返回 0 条 |
| 账户在当前企业下没有角色 | 无菜单、无数据 |
| 预览调用者无权配置目标角色 | 拒绝预览 |
| 规则保存成功但缓存未及时失效 | 缓存按「账户 + 企业」设短时效兜底，保存时主动失效 |

安全原则：

1. 行过滤、列处理、天花板校验全部在服务端完成；前端只做展示与输入约束。
2. 企业账户的硬隔离条件永远在最外层，任何规则都无法放宽。
3. 列表、详情、导出共用同一资源码，避免“列表隐藏了、导出却能拿到”。

## 11. 开发落地与分期

### 11.1 后端

| 项 | 做法 |
| --- | --- |
| 资源码 | 菜单权限标识前缀，不新增菜单字段 |
| 注解 | 在现有 dataScope 切面基础上扩展，例如 `@DataPermission(resource = "access:coreOrg", parties = {CORE = "t.core_org_id", FINANCER = "t.org_id"}, dept = "d", user = "u")` |
| 拦截器 | 硬隔离 → 合并后的行规则拼 WHERE；响应序列化时按列策略处理 |
| 规则表 | 新增 `SYS_DATA_RULE`；人员范围沿用 dataScope 取值与部门树接口 |
| 列策略 | 复用菜单列字段、角色列字段表与接口，角色改为差异语义；`/role/column/import` 保留兼容，不再是必经步骤 |
| 元数据接口 | 按菜单返回该列表声明的参与身份，供前端渲染可选项 |
| 缓存 | 按「账户 + 当前企业」缓存生效权限，规则保存时失效 |

### 11.2 前端

| 项 | 做法 |
| --- | --- |
| 配置组件 | 一个数据权限面板（行规则 + 列策略差异），角色配置权限页与用户组页复用；替换角色页目前不落库的前端模型与现有行级面板 |
| 矩阵 | 复用同一组件的只读 / 批量模式，挂在菜单管理 |
| 预览 | 删除前端列表对照表，可预览列表由后端按资源码给出 |

### 11.3 分期

```mermaid
flowchart LR
    subgraph S1["第一阶段 · 最小可用"]
        P1A["注解 + 拦截器 + 规则表"]
        P1B["企业硬隔离"]

        P1D["列策略改为差异"]

    end
    subgraph S2["第二阶段 · 复用与运营"]
```

## 12. 附录：v1.0 设计取舍对照

| v1.0 设计 | v2.0 处理 | 理由 |
| --- | --- | --- |
| 可视化条件构建器 | 不做，改为具名选项 | 开发成本最高、出错面最大；主体类型固定，两项选择已覆盖全部场景 |
| `$MY_DOWNSTREAM_ORGS$` 与关系网络自动派发 | 不做 | 单据参与方字段已表达关系；若出现“核心企业看下游企业的非单据档案”，再以具名选项基于准入关系实现 |
| 独立策略包实体 | 并入用户组 | 企业已绑定用户组，再加一层只增加概念 |
| 企业层默认绑定 | 并入用户组 | 企业类型差异由所绑定的用户组表达 |
| “本企业”预设档 | 改为系统硬边界 | 与现状一致，避免误配 |
| 规则四态状态机、字段漂移修复 | 改为派生显示状态（第 7 节） | 规则不再引用运营自填字段，漂移问题不存在 |
| 全平台角色矩阵 | 改为用户组矩阵 | 角色随企业增长，按组才可运营 |
| 多角色行规则“取宽松” | 按角色整体 OR | 按维度分别并集会越权 |
